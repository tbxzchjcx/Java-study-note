 第二章 类与对象的基本概念 完整总结

2.1 面向对象的程序设计方法概述

面向对象的程序设计（OOP）与结构化程序设计相比，更符合人类认识现实世界的思维方式，已成为程序设计的主流方向。它涉及四个主要概念：抽象、封装、继承和多态。

对象：现实世界中万物皆对象，每个对象都具有属性（状态）和行为。在程序中，一切都是对象，具有标识、属性和方法。对象通过变量保存状态，通过方法实现行为。

类：将属性及行为相同或相似的对象归为一类。类是对象的抽象，代表了该类对象共有的属性和行为。在面向对象程序中，每个对象都属于某个特定的类。

结构化程序设计：由若干程序模块（子程序或函数）组成，数据和功能分离，代码难以维护和复用。

面向对象程序设计：基本组成单位是类，程序运行时由类生成对象，对象之间通过发送消息进行通信，互相协作完成功能。

2.1.1 抽象

抽象是从具体事物中提取共同特征的过程。例如，钟表类可以抽象出属性（小时、分钟、秒）和方法（设置时间、显示时间）；人类可以抽象出属性（姓名、性别、年龄、身份证号）和方法（吃饭、走路、工作、学习等）。

2.1.2 封装

封装的定义包括三个方面：
清楚的边界：所有对象的内部信息被限定在这个边界内。
接口：对象向外界提供的方法，外界通过这些方法与对象交互。
受保护的内部实现：功能实现细节不能从类外访问。

封装的意义：
类封装了数据及对数据的操作，是程序中的最小模块。
禁止外界直接操作类中的数据，模块间只能通过严格控制的接口交互，降低耦合度。
保证模块具有较好的独立性，便于程序维护和修改。

2.2 类与对象

在程序中，对象是通过一种抽象数据类型——类（Class）来描述的。类是构造对象的模板，对象是类的具体实例。

2.2.1 类的声明

声明形式：
[public] [abstract | final] class 类名称 [extends 父类名称] [implements 接口名称列表] {
    变量成员声明及初始化；
    方法声明及方法体；
}

关键字：class 表明其后声明的是一个类；extends 用于继承父类；implements 用于实现接口。
修饰符：public（公有类）、abstract（抽象类）、final（终结类，不可被继承）。
类声明体包含变量成员和方法成员。

例2_1 钟表类：
public class Clock {
    int hour;
    int minute;
    int second;
    public void setTime(int newH, int newM, int newS) {
        hour = newH;
        minute = newM;
        second = newS;
    }
    public void showTime() {
        System.out.println(hour + ":" + minute + ":" + second);
    }
}

2.2.2 对象的声明与引用

引用变量：变量除了存储基本数据类型，还能存储对象的引用。类的对象也称为类的实例。
对象声明：类名 变量名;（例如 Clock aclock;），此时没有对象生成。
对象创建：变量名 = new 类名();（例如 aclock = new Clock();）。new 操作符在内存中分配空间并返回对象的引用。引用变量可被赋值为 null。

2.2.3 数据成员

数据成员表示Java类的状态。声明时必须给出变量名及类型，还可指定其他特性。成员变量名在类中唯一。类型可以是任意Java数据类型（简单类型、类、接口、数组）。

声明格式：
[public | protected | private] [static] [final] [transient] [volatile] 数据类型 变量名1[=初值], 变量名2[=初值], ...;

访问控制符：public、protected、private
static：静态成员变量（类变量）
final：值不能被修改
transient：临时状态（不参与序列化）
volatile：共享变量（用于多线程）

实例变量：没有 static 修饰的变量。每个实例有自己的副本，存储实例特有的属性信息。通过 <实例名>.<实例变量名> 访问。

例2_2：Circle类（含 int radius）和测试类ShapeTester。输出示例：Circle@26b249 和 radius = 0，证明实例变量默认初始化为0。

例2_3：Rectangle类（含 double width=10.128, double height=5.734），测试输出显示对象引用地址。修改后可分别设置不同实例的半径或宽高。

例2_4：地址簿程序对比：过程化方式需为每个人定义多个独立变量；面向对象方式定义Address类，包含姓名、门牌号、街道、城市、省份、邮编等属性，然后创建两个Address对象并分别赋值。代码更清晰、易维护。

类变量（静态变量）：用 static 修饰。无论有多少对象，类变量只存在一份，整个类共享一个值。在类初始化时赋值。适用于所有对象都相同的属性、需共享的数据或常量。

例2_5：在Circle类中增加 static double PI = 3.14159265;，所有Circle对象共享PI值。可通过 对象名.PI 或 类名.PI 访问。

例2_6（Point类）：用类变量 pointCount 记录已创建的点对象个数。构造方法中每次 pointCount++。测试结果显示计数正确。

final修饰符：实例变量和类变量都可声明为 final。final实例变量必须在每个构造方法结束前赋值；final类变量必须在声明时初始化。

2.2.4 方法成员

方法成员定义类的行为，包括对象能做的事情以及能从对象获取的信息。分为实例方法和类方法。

声明格式：
[public | protected | private] [static] [final] [abstract] [native] [synchronized] 返回类型 方法名([参数列表]) [throws exceptionList] {
    方法体
}

修饰符说明：
public/protected/private：存取控制
static：类方法（静态方法）
final：终结方法（不可被重写）
abstract：抽象方法（无方法体）
native：集成其他语言代码
synchronized：控制并发线程访问

返回类型：可以是任意Java数据类型，无返回值时用 void。
参数：简单类型或引用类型（数组、类、接口）。方法声明时的参数称为形式参数。
方法体：包含局部变量声明和合法指令，局部变量作用域只在方法内部。
throws：声明可能抛出的异常。

方法调用：给对象发消息即调用对象的方法。格式：<对象名>.<方法名>([参数列表])。点操作符前的对象名是消息的接收者。参数传递：基本类型是值传递，对象类型或数组是引用传递。

实例方法：不加 static 修饰，表示特定对象的行为，必须通过类实例调用。

例2_6：Circle类中增加 public double circumference() 方法，计算圆的周长。测试时两个不同半径的圆分别返回正确的周长。

例2_7：Circle类和Rectangle类各自声明 area() 方法，测试类分别调用，系统根据接收者对象的类型找到相应类的方法。

例2_8：带参数的方法 enlarge(int factor)，扩大圆的半径。测试显示扩大后周长变化。

例2_9：以对象为参数的方法 fitsInside(Rectangle r)，判断圆是否在矩形内。

类方法（静态方法）：用 static 修饰，表示类中对象的共有行为。可在不创建对象的情况下通过类名直接调用，也可用实例调用。不能被声明为抽象。

例2_10：温度转换方法 centigradeToFahrenheit 放在类Converter中，直接通过 Converter.centigradeToFahrenheit(40) 调用。

2.2.5 类的组织——包的概念

包（Package）：一组类的集合，可以包含若干个类文件和其他包。

包的作用：
将相关源代码文件组织在一起。
类名空间管理，避免类名冲突。
提供包一级的封装及存取权限。

包的命名：应保证唯一性。建议将机构Internet域名反序作为包名前导，如 com.example.project。包名全小写，必要时用下划线处理非法字符或关键字冲突。

编译单元：一个Java源代码文件是一个编译单元，包含三部分：
1. 所属包的声明（package 语句，省略则属于默认包）。
2. 引入包的声明（import 语句）。
3. 类和接口的声明。

一个编译单元中只能有一个 public 类，且该类名必须与文件名相同。编译后每个类生成一个 .class 文件。

包的声明：package Mypackage;。不含有包声明的编译单元属于默认包。

包与目录：Java使用文件系统存储包和类，包名对应目录名。编译和运行时通过 CLASSPATH 环境变量指定查找路径。

引入包：使用 import 语句引入其他包中的类。import package1.package2... .classname; 或 import package1.package2... .*;。Java编译器自动为所有程序引入 java.lang 包。

2.2.6 类的访问控制

类的访问控制：只有 public（公有类）和无修饰符（缺省类）两种。public 类可被任何包中的类访问；缺省类只能被同一包中的类访问。

类成员的访问控制：

private：只能被本类访问。
无修饰符（default）：仅允许同一包内访问（包访问权限）。
protected：可被同一包及其子类访问。
public：可被任何对象访问（前提是对类有访问权限）。

具体访问能力表：
private：同一类 是，同一包子类 否，同一包非子类 否，不同包子类 否，不同包非子类 否
无修饰符：同一类 是，同一包子类 是，同一包非子类 是，不同包子类 否，不同包非子类 否
protected：同一类 是，同一包子类 是，同一包非子类 是，不同包子类 是，不同包非子类 否
public：同一类 是，同一包子类 是，同一包非子类 是，不同包子类 是，不同包非子类 是

例2_11：将Circle类的 radius 声明为 private，在测试类中直接 c1.radius=50; 会导致编译错误。需要通过公有的 get 和 set 方法访问。

get 方法：用于获取属性值，通常格式为 public <fieldType> get<FieldName>() { return <fieldName>; }
set 方法：用于修改属性值，格式为 public void set<FieldName>(<fieldType> <paramName>) { <fieldName> = <paramName>; }
this 关键字：当形参与实例变量同名时，使用 this.实例变量 区分。

2.3 对象初始化和回收

2.3.1 构造方法

构造方法是一种与类同名的方法，用于初始化新创建的对象。Java中的每个类都有构造方法。

构造方法的特点：
方法名与类名相同。
没有返回类型，也不能写 void。
通常声明为 public。
可以有任意多个参数。
主要作用是完成对象初始化。
不能在程序中显式调用，而是在 new 生成对象时由系统自动调用。

默认构造方法：如果类中没有声明任何构造方法，Java编译器会提供一个默认的无参构造方法，方法体为空。使用默认构造方法时，实例变量会被初始化为默认值（数值为0、布尔为false、引用为null）。

例2_12：BankAccount类未定义构造方法，使用默认构造方法创建对象后，输出 ownerName=null、accountNumber=0、balance=0.0。

自定义构造方法与方法重载：可以在生成对象时传递初始值。构造方法可以重载（同一类中多个同名构造方法，参数列表不同）。

例2_13：为BankAccount定义三个参数的构造方法（姓名、账号、余额），以及两个参数的构造方法（姓名、账号，余额默认0.0f）。

自定义无参构造方法：如果类中定义了有参构造方法，系统不再提供默认无参构造方法。但为了子类初始化的方便，建议至少声明一个无参构造方法。例如例2_14中显式定义无参构造方法，将ownerName设为空串，accountNumber设为999999，balance设为0.0f。

例2_15（Tree类）：演示构造方法重载和方法的覆盖。Tree类有无参构造（高度0）和有参构造（指定高度），以及重载的 info() 方法。测试类Overloading输出不同树的信息。

this 关键字调用其他构造方法：可以使用 this(参数列表) 在一个构造方法中调用本类的另一个构造方法，使代码更简洁。通常参数少的构造方法调用参数多的构造方法。

例2_16：修改BankAccount类，无参构造调用 this("", 999999, 0.0f)，二参数构造调用 this(initName, initAccountNumber, 0.0f)。

2.3.2 内存回收技术

无用对象：当对象不再被使用时（如离开作用域或引用被赋值为 null），成为垃圾。

垃圾收集器：Java运行时系统自动扫描动态内存区，标记不再使用的对象并回收内存。垃圾收集器通常作为一个低优先级线程在系统空闲时异步运行；当内存用尽或调用 System.gc() 时，会同步执行。

finalize() 方法：定义在 java.lang.Object 中，每个类都有。在垃圾收集器回收对象之前自动调用，用于释放系统资源（如关闭文件、Socket等）。如果需要释放除内存外的资源，应重写 finalize() 方法，声明为 protected void finalize() throws Throwable。

与C/C++的区别：C用 free、C++用 delete 手动释放内存，容易造成内存泄漏；Java自动管理内存，不会发生内存泄漏，但对其他资源（如文件句柄）仍需注意释放。

2.5 UML简介

UML（统一建模语言）是面向对象设计的标准图形化建模语言。

2.5.1 类图

类图由类和它们之间的关系组成，定义系统中的类，表示类的内部结构（属性和操作）以及类之间的关系。类图是构建其他图的基础。

类的图形表示：分为三部分：类名、属性、操作（方法）。可以省略操作或属性部分。

示例：BankAccount类的图形表示为包含accountNumber、ownerName、balance属性和withdraw、deposit操作。

类的关系表示：

关联：描述对象间的离散连接，包括普通关联、聚集和组成。

聚集（Aggregation）：表示部分与整体关系，用端点带有空心菱形的线段表示，菱形连接整体类。例如一个人可以参加多个课题组，课题组包含多个人。

组成（Composition）：更强的整体-部分关系，部分与整体共存，整体消失则部分消失。用实心菱形表示。例如Windows窗体由菜单、按钮等组成，窗体销毁则这些组件也随之销毁。

泛化（Generalization）：即继承关系，用从子类指向父类的空三角形箭头表示。子类完全拥有父类的属性和操作，并可添加额外信息。遵循里氏替换原则：父类出现的地方都可以用子类替换。

2.5.2 对象图

对象图是类图的实例，帮助理解复杂的类图。表示形式与类图相似，但对象名下加下划线。对象名有三种格式：对象名: 类名、: 类名（匿名对象）、对象名。

扩展说明：

构造方法不能被子类继承，但子类可以通过 super 调用父类的构造方法。

静态方法不能直接访问实例变量或实例方法，因为静态方法不依赖于具体对象。

实际开发中通常将实例变量设为private，通过public的getter/setter暴露访问，这符合封装原则，便于后续增加验证逻辑或改变内部实现。

Java的垃圾收集器具体回收时机不确定，System.gc() 只是建议JVM进行垃圾回收，不一定立即执行。

UML类图中，还可以标注多重性（如 1..*、0..1 等），在关联线上表示数量关系。
